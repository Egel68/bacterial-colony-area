# Design

## Context

Проверка текущего COCO-источника `datasets/22022540` подтвердила, что все 369 размеченных изображений локальны, декодируются и совпадают по размерам с аннотацией. В `datasets/22022540_imported` находятся 738 пар изображения/маска, все файлы читаются, но отсутствует `split.json`, поэтому этот каталог нельзя непосредственно передать в текущий режим повторного использования датасета.

Сейчас `train-colony` сам запускает импорт перед baseline-оценкой и обучением: изображения записываются повторно, маски растеризуются из COCO-боксов, split сохраняется, а для black-background эксперимента дополнительно создаются варианты с чёрным фоном. `ColonyPatchDataset` затем вырезает 512×512 фрагменты и применяет случайные преобразования в памяти. Это нужно разделить на локальную подготовку перед архивированием и обучение из готового набора.

В репозитории уже есть зависимость `zstandard` в дополнительном окружении `dev`; полное обучающее окружение включает `dev`. `.gitignore` исключает `datasets/*_imported/`, `train/data/` и `train/runs/`; `.gitattributes` с правилами Git LFS пока нет.

## Goals / Non-Goals

**Цели:**
- Перед упаковкой проверять все размеченные COCO-изображения и локально материализовать полный набор файлов, реально используемых текущим `train-colony`: исходные изображения, бинарные маски, фиксированный split и black-background варианты, если они включены.
- Передавать подготовленные бинарные данные в Git LFS одним lossless-архивом `.tar.zst`; сохранить текстовые аннотации и манифесты доступными для просмотра в обычном Git.
- Обучать только на проверенном, распакованном наборе; не создавать файлы изображений/масок во время запуска обучения.
- Сохранить текущую генерацию случайных 512×512 patches и аугментаций в памяти.

**Не входит в цели:**
- Перекодирование исходных фотографий с потерями ради уменьшения размера, замена формата пикселей или обещание заранее заданного коэффициента сжатия.
- Сохранение каждого случайного patch/аугментации как отдельного файла: это увеличило бы архив и изменило бы выборку между эпохами.
- Перенос `test_images/` в LFS, изменение модели/loss/inference или отслеживание `train/data/` и `train/runs/`.
- Автоматическое добавление, коммит или отправка локальных исходников и подготовленного архива.

## Decisions

### Упаковывать готовые бинарные данные в lossless `.tar.zst`

В LFS хранится архив `datasets/archives/22022540-training-webp.tar.zst`, а не отдельные распакованные фото и маски. Использовать Zstandard с высоким уровнем сжатия (начальный профиль — level 19), детерминированный порядок файлов и нормализованные метаданные tar; архив содержит весь подготовленный набор и требуемые манифесты. Текстовые копии манифестов и COCO-аннотаций остаются обычными файлами Git и должны совпадать с копиями в архиве. Распакованное дерево `datasets/work/22022540-training-webp/` остаётся локальным и игнорируемым.

Упаковщик SHALL сохранять байты подготовленных файлов без повторного кодирования. Первый архив для PNG-вариантов занял 2,620,705,068 bytes, то есть превышал 2 GB per-file limit планов GitHub Free/Pro. Поэтому производные black-background изображения записываются в lossless WebP (`cv2.IMWRITE_WEBP_QUALITY=101`) с проверкой точного массива пикселей после чтения; исходные JPEG копируются байт-в-байт, маски остаются PNG. Это меняет только кодирование производного варианта, не размеры и не пиксели. JPEG уже сжат, поэтому lossless Zstandard всё ещё может мало уменьшать архив; фактический размер/коэффициент необходимо записывать и проверять до отправки, не обещая заданного процента. Любое lossy-перекодирование требует отдельного решения владельца. Текущий lossless-WebP snapshot упакован в 1,769,193,978 bytes при 1,785,071,333 uncompressed (archive/uncompressed=0.9911054787, factor=1.0089743438); SHA-256 round-trip подтверждён, точные метрики и хеш записаны в sidecar `.archive.json`. Размер ниже per-file limit 2 GB для GitHub Free/Pro.

### Отделить предварительную подготовку и проверку от обучения

Добавить отдельную локальную команду `prepare-colony-training`, принимающую COCO-каталог, путь результата, seed/доли split и опцию black-background. До создания результата она проверяет для каждого изображения с аннотациями наличие файла, декодирование OpenCV и совпадение размеров с COCO. Затем создаёт полный набор изображений/масок, `dataset.json`, `split.json` и включённые производные варианты, проверяет все ссылки и формирует архив. Ошибка любого входа останавливает подготовку до архивации; push в GitHub команда не выполняет.

Существующий `datasets/22022540_imported` не переиспользовать напрямую: в нём нет требуемого `split.json`, а текущий train-colony workflow не получает из него black-background набор. Готовить новый самодостаточный training snapshot из проверенного COCO-источника.

### Обучать из распакованного подготовленного набора

Изменить `train-colony`, чтобы он принимал локальный корень готового набора и проверял `dataset.json`, `split.json` и все файлы до baseline-оценки/обновления весов. Обучающая команда не вызывает импорт COCO, не растеризует маски и не записывает/перекодирует изображения или чёрнофоновые варианты. Она использует сохранённые split и файлы; 512×512 patches и случайные трансформации по-прежнему формирует в памяти, не сохраняя их на диск.

Отдельная команда `uv run augment`, которая заранее создаёт пары в `train/data/`, остаётся вне этого COCO-архива и не меняет текущих правил игнорирования. Её результат не является частью `train-colony` black-background набора.

### Отслеживать архивы, а не распакованные рабочие деревья

Добавить LFS-атрибут только для архивов `.tar.zst` под `datasets/archives/`. Не применять LFS к отдельным `.jpg`/`.png` распакованного датасета. Сохранить игнорирование локальных импортированных/распакованных каталогов, добавить исключения для архивов и текстовых sidecar-файлов и проверить фактические правила `git check-attr`/`git check-ignore`. `test_images/` остаётся вне шаблонов LFS.

### Документировать получение, проверку и явную отправку

Инструкции должны описывать установку Git LFS, `git lfs pull`, проверку наличия полного архива, распаковку в ожидаемый локальный каталог, сверку манифеста и запуск обучения. Первоначальный `git add`/commit/`git push` остаётся явным действием владельца после проверки лицензии, видимости репозитория и квоты. Указать актуальную документацию GitHub, не фиксированное обещание квоты.

## Risks / Trade-offs

- [JPEG уже сжат] → Lossless `.tar.zst` может дать ограниченную экономию на исходных фотографиях; измерять реальный результат на подготовленном наборе до LFS push и не обещать размер заранее.
- [Высокий уровень Zstandard медленнее и потребляет больше CPU/памяти] → Выполнять упаковку только в локальном подготовительном шаге и записывать размер/время результата.
- [Неактивный Git LFS или нераспакованный архив] → Проверять наличие полного archive и файлов манифеста до baseline-оценки; в ошибке направлять пользователя к установке Git LFS, `git lfs pull` и распаковке.
- [Квота, стоимость или лицензия не подходят] → Не отправлять архив автоматически; требовать явной проверки перед публикацией и ссылаться на актуальные условия GitHub.
- [Sidecar-манифесты разошлись с содержимым архива] → Сверять их хеши и все пути `image`/`mask` при упаковке и после распаковки.

## Migration Plan

1. Реализовать подготовительную команду с предварительной проверкой COCO-ссылок и тестами на отсутствующий, нечитаемый и неверного размера файл.
2. Локально создать training-ready дерево с масками, фиксированным split и требуемыми black-background вариантами; проверить все пары и соответствие split.
3. Упаковать бинарные данные в `.tar.zst` без изменения их байтов, проверить архив полным round-trip и записать размер/коэффициент сжатия. До проверки владельцем не добавлять архив в Git и не отправлять его.
4. Изменить `train-colony` на приём распакованного полного набора; добавить тесты, подтверждающие ранний отказ при пропусках и отсутствие записи файлов изображений/масок при обучении.
5. Настроить Git LFS только для архивов, оставить распакованные деревья локальными, обновить инструкции по подготовке, квотам, лицензиям, отправке и получению; проверить, что `test_images/`, `train/data/` и `train/runs/` не перемещены в LFS.
6. После локальной проверки владелец явно добавляет, коммитит и отправляет архив. На чистом checkout проверить `git lfs pull`, распаковку, манифест и тренировочный запуск на готовых файлах.

До отправки откат ограничивается возвратом конфигурации и удалением локально созданных архивов/деревьев. После отправки LFS-объектов удаление и очистку истории нужно согласовывать отдельно: удаление Git-указателя не гарантирует немедленного освобождения квоты.
