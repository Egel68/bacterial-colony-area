## Context

Капабилити `colony-analysis` уже реализована в коде: `ColonyDetector` (детекция чашки и колоний), `ImageProcessor` (предобработка), `AnalysisParams`/`PetriInfo`/`AnalysisResult` (typed данные), `AreaCalculator` (площади), `AnalysisController` (Qt-free оркестрация). Задача change — задокументировать контракт в спеке и сверить с существующим кодом и тестами (reverse documentation). Логика алгоритма не меняется.

## Goals / Non-Goals

**Goals:**
- Зафиксировать спекой контракты: обнаружение чашки (два пути), валидацию параметров, пайплайн детекции, расчёты площадей.
- Убедиться, что каждый сценарий спеки закрыт кодом и (по возможности) тестом.
- Сохранить обратную совместимость: ноль изменений поведения.

**Non-Goals:**
- Изменение алгоритмов детекции или предобработки.
- Добавление новых параметров или форматов.
- Переписывание `analysis/`.

## Decisions

1. **Два пути поиска чашки — фиксируем как есть.**
   Основной путь — яркие объекты (порог 200) с отбором контура по критериям (area ≥ 10%, близость к центру ≤ 30%), `minEnclosingCircle`. Fallback — `HoughCircles`. При отсутствии результата — `(None, None)`.
   Rationale: текущая реализация эмпирически работает на фото чашек тёмного поля; документируем существующее, не меняя порогов.

2. **Валидация через `AnalysisParams.__post_init__` (assert).**
   Диапазоны фиксируются в докстрин-контракте спеки. Rationale: существующая реализация использует контракты; спека должна повторять их 1-в-1.

3. **Пайплайн как единый контракт `detect_colonies`.**
   Все внутренние шаги (канал, CLAHE, blur, bg-вычитание, адаптивный порог, морфология, connected components) фиксируются в порядке следования; параметры порога привязаны к `sensitivity`. Эта привязка — сверить соответствие с `colony_detector.py`.

4. **Расчёт площадей — через `AreaCalculator`, mm-коэффициенты завязаны на диаметр чашки 90 мм.**
   Документируем формулы: внутренний радиус с учётом margin, коэффициент px_to_mm2, покрытие %.
   Rationale: сменные гипотезы размера чашки (другой диаметр) в текущей версии API не поддерживаются, поэтому в спеке фиксируем значение по умолчанию.

5. **`AnalysisController` — тонкая обёртка.**
   Контракт: `find_petri_dish`, `analyze`, свойства `colony_mask`/`debug_images`. Qt не участвует.

## Risks / Trade-offs

- **[Параметры в assert]** `AssertionError` не является пользовательским типом ошибки → *Приемлемо: контролируется интерфейсом до вызова, для unattended вызовов требуется валидация на уровне UI.*
- **[Фиксированные пороги (200, 101, −10)]** — могут не работать на других типах изображений → *Документируется как текущее поведение, вне Non-Goals расширение.*
- **[Диаметр 90 мм захардкожен]** — физический размер чашки может отличаться → *Принимается как константа по умолчанию; API позволяет передать другой диаметр через `AreaCalculator(diameter)`.*

## Migration Plan

Не требуется: существующий код не изменяется, спецификация — это обратная документация.
