## Why

Сегодня обучение привязано к единственному источнику данных: `ColonyDataset`/`make_datasets` читает пары по жёстко зашитой конвенции `data_root/images/` + `masks/` (совпадающие имена), а разметка пишет данные в другую структуру (`source/` + `masks/`, `cropped/` + `cropped_masks/`, суффикс `_mask`). Из-за этого размеченные сессии нельзя напрямую использовать для обучения, а внешние датасеты вообще не подключить без правок ядра. Нужен единый, универсальный **контракт данных**: канонический формат «пары + манифест», который потребляется напрямую из pipeline разметки и в будущем — из внешних источников, при этом сам цикл обучения не знает ни об одном конкретном формате.

## What Changes

- **Канонический контракт данных** (новая capability `training-data-contract`): датасет = манифест `dataset.json` + пары «изображение/маска». Обучение работает с контрактом, а не с «угадыванием структуры папок» ветвлением `if` в ядре.
- **Сессия разметки — родной источник**: адаптер сканирует структуру сессии (`source/`+`masks/`, `cropped/`+`cropped_masks/`, суффикс `_mask`) и строит манифест на лету, без конверсии и копирования файлов. Разметил → сразу можно учить.
- **Две стратегии хранения файлов**: `reference` (манифест ссылается на файлы по относительному пути, ничего не копируется — родной режим для сессий разметки) и `copy` (файлы материализуются в `data_root`, получается самодостаточная переносимая папка). Обе поддерживаются контрактом; для внешних источников стратегию выбирает импортёр на будущее.
- **`mask_mode`**: сейчас `binary` (один класс). Поле в манифесте резервирует `multiclass` на будущее; обучение пока работает только с бинарными масками, контракт проверяет режим и даёт понятную ошибку при несовместимости.
- **Выброс старой привязки данных**: `make_datasets` перестаёт различать форматы; легаси `images/` + `masks/` читается через тот же контракт одним из адаптеров (по-прежнему работоспособен, но уже не «особый случай» в ядре обучения).
- **Многоархитектурное обучение и сравнение** (сохраняется из предыдущей версии change): реестр `@register_model` с `unet` и `unet_small`, конвейер `train-compare` с оценкой `best.onnx`, метрики в реальном времени (rich/dashboard + TensorBoard), обучение на CUDA с CPU-фолбэком, ONNX-экспорт для CPU-инференса.
- **Импортёры внешних данных — задел (не реализуем сейчас)**: интерфейс импортёров и манифест-контракт задокументированы в `design.md`, чтобы будущие COCO / VOC / произвольные пары подключались без изменения ядра обучения.

## Capabilities

### New Capabilities

- `training-data-contract`: канонический формат данных обучения (манифест + пары), адаптеры источников (сессия разметки, манифест, легаси-пары), стратегии хранения `reference`/`copy`, `mask_mode` с резервом под `multiclass`.
- `multi-architecture-training`: выбор архитектуры через конфиг/CLI, обучение нескольких CNN-архитектур на CUDA с CPU-фолбэком, метрики в реальном времени, оценка `best.onnx` на тестовых парах и сравнительный отчёт.

### Modified Capabilities

- `unet-training`: меняется требование загрузки данных (чтение через контракт `training-data-contract` вместо жёсткой привязки к `images/`+`masks/`) и требование реестра моделей (несколько регистрируемых архитектур с настраиваемыми параметрами).

## Impact

- `train/dataset_manifest.py` (новый) — схема манифеста, валидация `mask_mode`, конструкторы записей.
- `train/dataset_adapters.py` (новый) — адаптеры источников: `ManifestAdapter`, `LabelingAdapter`, `PairsAdapter` (легаси), фабрика `load_manifest`.
- `train/dataset.py` — `make_datasets`/`ColonyDataset` читают контракт; логика разделения train/val уходит в манифест (с фолбэком на seed-сплит при отсутствии `subset`).
- `train/models/` — новые архитектуры (`unet_small` и др.), расширение реестра.
- `train/train.py`, `train/main.py`, `train/compare.py` — конвейер и CLI `train-compare`.
- `testing/` — переиспользуется без изменений (`TestDataset`, `OnnxModelAlgorithm`, `compute_segmentation_metrics`).
- Данные: сессии разметки и `test_images/` используются напрямую; `train/data` (легаси `images`+`masks`) подключается адаптером пар.
- Зависимости без изменений: PyTorch (CUDA) в `.venv-full`, `onnxruntime` в `.venv-full`.
- Документация: `AGENTS.md` получит раздел о резерве импортёров и контракте данных, чтобы задел не потерялся.
