## Why

Тестирование алгоритмов распознавания колоний сейчас существует только как CLI (`uv run test-algorithms`) с фиксированным набором из 4 классических алгоритмов. Нет графического интерфейса, нельзя подключать нейросетевые модели (обученный U-Net в `train/` генерирует `.onnx`, но не участвует в тестировании), нет выбора алгоритмов/датасета и парного сравнения. В результате сравнение алгоритмов — это ручной процесс для разработчика, а не доступная пользователю функция приложения.

## What Changes

- **GUI-окно «Тестирование алгоритмов»** в PyQt-приложении: выбор датасета (`source+cropped`), выбор алгоритмов (чекбоксы), запуск прогона, таблица метрик, экспорт HTML-отчёта.
- **Универсальный фреймворк ML-моделей**: новые алгоритмы могут быть реализованы в виде ONNX-моделей (U-Net и др.) и регистрироваться в существующий реестр через общий интерфейс `BaseDetectionAlgorithm`.
- **Поддержка двух источников весов NN:** (1) внешний файл весов `.onnx`, который выбирается/подгружается без пересборки приложения; (2) встроенные веса, упакованные в исполняемый файл (опционально, для дистрибуции без внешних файлов).
- **Выбор алгоритмов для прогона** (сейчас `run_all` всегда гоняет весь реестр) и выбор структуры отчёта — сводные метрики по выборке опционально per-image.
- **Парное сравнение алгоритмов A vs B** на одних и тех же изображениях (победитель по каждому снимку/метрике).
- CLI остаётся и расширяется: флаг `--algorithms` для выбора, поддержка тестовых моделей, общий с GUI код ядра.
- **BREAKING:** интерфейс `BaseDetectionAlgorithm.detect()` не меняется, но registration расширяется на модели с весами (нужен механизм описания/вания параметров) — старые алгоритмы продолжают работать без изменений.

## Capabilities

### New Capabilities
- `algorithm-testing-gui`: графическое окно тестирования в приложении — выбор датасета, алгоритмов и моделей, запуск прогона, таблица метрик, экспорт отчёта.
- `neural-model-algorithms`: подключение нейросетевых моделей (ONNX) как алгоритмов детекции — внешние и встроенные веса, инференс, нормализация до универсальной бинаrной маски.

### Modified Capabilities
- `algorithm-testing`: расширяется набор требований — выбор алгоритмов для прогона (`--algorithms`), опциональные per-snapshot метрики, парное сравнение A vs B, поддержка ONNX-моделей в реестре наравне с классическими алгоритмами.

## Impact

- **Код:** `testing/interface.py`, `testing/registry.py`, `testing/runner.py`, `testing/dashboard.py`, `testing/dataset.py`, `testing/classic_algorithms.py`, `training/predict.py` (рефакторинг под общий интерфейс), `ui/` (новое окно), `main.py` (кнопка запуска), `train/models/` (экспорт ONNX).
- **Зависимости:** `onnxruntime` (уже в `.venv-full`, должен подгружаться lazily; в GUI — проверка доступности), Nuitka-упаковка для встроенных весов.
- **Окружения:** `.venv` (runtime) пока НЕ включает onnxruntime; GUI должен обрабатывать отсутствие моделей как пустой список.
- **Данные:** `test_images/` остаётся источником.

## Non-goals
- Не реализуем обучение новых моделей — только подключение обученных `.onnx` к тестированию.
- Не добавляем REST/веб-API тестирования.
