# Design: add-colony-segmentation-model

## Context

Проект обучает U-Net бинарной сегментации (255 = колония) через `train.main train`.
Ядро обучения потребляет манифест `DatasetManifest`/`dataset.json` через фабрику
`load_manifest` и адаптеры `train/dataset_adapters.py`. Уже есть готовые пути
интеграции моделей как алгоритмов: ONNX-модель, положенная в `models/*.onnx`,
автоматически регистрируется как `OnnxModelAlgorithm` (bundled), либо загружается
как внешний файл через GUI/CLI.

Источник `datasets/22022540` — **формат детекции** (боксы), а не маски:
- `annot_COCO.json` (56 865 боксов, 24 класса sp01–sp24), дубли-форматы TSV/YOLO/VOC;
- снимки полных чашек 2800–5600 px, по одному виду на снимок, плотность 2–747 колоний.

Задача: привести эти данные к контракту обучения и получить обученную бинарную
сегментационную маску «наличие колонии», интегрируемую в проект без неизвестного
кода.

## Goals / Non-Goals

**Goals:**
- Импортёр COCO-bbox → бинарные маски + самодостаточный датасет с `dataset.json` (читается `ManifestAdapter`).
- CLI `import-22022540` без GUI.
- Обучение U-Net на этих данных через существующий конвейер; ONNX-экспорт.
- Интеграция `best.onnx` как алгоритма детекции (bundled или внешний).

**Non-Goals:**
- Многоклассовая сегментация (классы бактерий) — конвейер поддерживает только `binary`.
- Создание идеальных попиксельных масок — грубые маски из боксов это weak supervision.
- Изменение контракта/ядра обучения (`load_manifest`, `make_datasets`).

## Decisions

### D1. Входной формат — COCO, не TSV/YOLO/VOC
COCO (`annot_COCO.json`) — единственный источник со всеми 56 865 боксами и списком
изображений в одном JSON; TSV-файл избыточен, YOLO/VOC — ZIP-дубли той же разметки.
**Альтернативы:** парсинг TSV (проще, но только 1 из 4 форматов) — отклонено в пользу
COCO как канонического и самодостаточного. YOLO/VOC оставлены как вспомогательный
источник на случай расхождений (верификация в D5).

### D2. Растризация бокса → круг/полигон, не просто прямоугольник
Колонии в 22022540 круглые, боксы ~55–64 px вокруг них. Заливка прямоугольника
включает фон внутри углов. Решение: заливать **вписанный эллипс** в каждый бокс
(центр + половинки ширины/высоты как радиусы), что ближе к реальной форме и
уменьшает ложноположительный фон.
**Альтернативы:** (а) чистый прямоугольник — проще, но больше фона в маске;
(б) WBC/круглая аппроксимация по `min(w,h)/2` — менее точно для вытянутых колоний.
Выбрана эллиптическая заливка как компромисс точности и простоты.

### D3. Форма выхода датасета — `dataset.json` через новый адаптер-импортёр, `storage="copy"`
Импорт материализует копии `source/*.jpg` + `source/*_mask.png` (и опционально
`cropped/`) и пишет `dataset.json` со схемой `training-data-contract`
(`mask_mode="binary"`, `origin="external"`, `dish` для source). Это использует
существующий `ManifestAdapter` — **ядро обучения и фабрика не меняются**.
**Альтернативы:** (а) `LabelingAdapter`-структура `source/`+`masks/` — не несёт
`dish`/`origin=external` и требует именно `{stem}_mask`-имен; (б) легаси `PairsAdapter` —
без `dish`. `dataset.json` выбран, т.к. контракт уже предусматривает внешних
импортёров (задел в `dataset_adapters.py`) и максимально полон.

### D4. Pre-обрезка по чашке (`kind=cropped`) — опционально, по умолчанию выключена
Обрезка по чашке (чёрный фон вне круга) резко снижает долю фона и приближает данные
к тому распределению `cropped/`, на котором обучается пайплайн проекта.
По умолчанию импорт создаёт `source`; флаг `--crop` добавляет `cropped`-пары.
**Компромисс:** обрезка уменьшает общее число уникальных геометрий для аугментации
и требует авто-поиска чашки (D6). Оставлено включаемым, чтобы не дублировать объём
данных без необходимости.

### D5. Автопоиск геометрии чашки (`dish`) + верификация по YOLO/VOC
`dish.{cx,cy,r}` вычисляется авто-поиском (HoughCircles/наименьшая окружность вокруг
периферии — переиспользуется логика `analysis/colony_detector.py`). Для контроля
корректности растризации импорт выполняется сверкой числа масок на снимок с числом
боксов из COCO **и** YOLO/VOC-дублей; при расхождении > порога — предупреждение.
**Риск:** авто-поиск чашки может ошибаться на тёмных снимках → `dish` помечается
как условный, а при `--crop` ошибки заметны по чёрным артефактам на реальных
колониях.

### D6. Архитектура и обучение — существующий U-Net + конфиг, `img_size` масштабируется
Пятно сегментации бинарное, колоний 56k — используем штатный `train/models/unet.py`,
BCE+Dice loss, `--img-size 512`, seed-сплит train/val от `val_split` (в манифесте
`subset` не задаём — сплит делает `make_datasets`). Полноразмерные 3000–5600 px
масштабируются через ресайз в датасете (кроп не обязателен для обучения).
**Альтернативы:** `unet_small` — быстрее, но меньше качество на плотных чашках;
выбрано обучение U-Net с последующим сравнением, если метрики низкие.

### D7. Интеграция — bundled ONNX (без изменения кода), внешний ONNX как запасной
`best.onnx` кладётся в `models/` → `OnnxModelAlgorithm` (из `neural-model-algorithms`)
регистрирует его автоматически при старте; сигнатура `detect(image)->uint8 mask`
совпадает с выходом нашей модели (бинарная маска + порог 0.5).
**Альтернативы интеграции (задокументированы как варианты для заказчика):**
1. **Bundled** — основной; нулевые изменения кода, модель внутри бинарника.
2. **Внешний ONNX** — загрузка через GUI/CLI без пересборки (уже поддержано).
3. **Новый адаптер** — только если понадобится кастомная постобработка (напр. слияние
   с классическим детектором); в текущем скоупе не требуется.
Если у выходной маски требуется выравнивание по контуру чашки/отступ от края
(как у классических алгоритмов) — это делается постобработкой на стороне
`OnnxModelAlgorithm` вызовом уже существующих утилит, без изменения интерфейса.

## Risks / Trade-offs

- **Грубые маски из боксов (слабый GT)** → Режим «weak supervision»: обучение начинается с них, редкие ошибки компенсируются Dice-потерей; при низком качестве планируется доразметка трудных снимков в labelling и дообучение.
- **Авто-поиск чашки на тёмных/плотных снимках** → `dish` используется только для `--crop`; для source-обучения не обязателен. Ошибки `--crop` видны как чёрные вырезы по реальным колониям → ручной пересчёт по образцу.
- **Дисбаланс плотности 2 vs 747 колоний** → Тренировка на `img-size 512` и ст.слой в батче (`make_datasets`) сглаживают; при необходимости — стратификация выборки отдельным шагом.
- **Перенос распределения `cropped`-пайплайна** → Модель обучается на full/cropped; при разметке исходников vs обрезков гистограмма может отличаться — агностицируется сильной аугментацией (`train/augment.py`).
- **COCO как единственный источник** → Верификация по YOLO/VOC-дублям в D5; при расхождении форматов — TSV как третий независимый источник.

## Open Questions

- Целевой порог метрики для приёмки модели (IoU/Dice на валидации) — предложен `Dice ≥ 0.6` на плотных валидационных чашках, подтвердить при первом прогоне.
- Нужна ли версия `unet_small` для встраивания в бинарник меньшего размера, или оставляем полный U-Net.
