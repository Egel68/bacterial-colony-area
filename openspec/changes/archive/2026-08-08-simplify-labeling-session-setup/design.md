## Context

Пользователь работает с собранным бинарником (`BacteriaAnalyzer`). При нажатии «✏️ Разметка тестовых изображений» в `MainWindow._open_labeling` (ui/main_window.py:173) открывается стандартный диалог выбора папки, и затем `LabelingWindow` (labeling/labeling_window.py) сканирует корень сессии на предмет внутренних поддиректорий `source/`, `masks/`, `cropped/`, `cropped_masks/`, при их отсутствии работая с корнем сессии (fallback в `ui/controllers/labeling_controller.py`). Структура директорий является внутренней деталью реализации, но сейчас ею управляет пользователь, что непонятно и неудобно.

Ограничения: приложение — десктоп-инструмент PyQt6, собирается Nuitka-бинарником; логика на стороне контроллера тестируется без Qt (tests/ есть для метрик/расчётов). UI — русскоязычный, комментарии в коде — на русском.

## Goals / Non-Goals

**Goals:**
- Понятный пользователю вход в разметку: диалог «Новая сессия разметки» с полем названия.
- Автоматическое создание структуры сессии (root + 4 поддиректории) без участия пользователя.
- Список недавних сессий для быстрого повторного открытия (сохраняется между запусками).
- Сохранение возможности открыть произвольную папку (продвинутый пользователь/миграция старых данных).

**Non-Goals:**
- Изменение процесса разметки/кисти/обрезки внутри окна разметки.
- Перенос/авто-миграция старых сессий между устройствами.
- Сохранение настроек самого анализа.
- Онлайн-синхронизация или командная работа.

## Decisions

### 1. Отдельный компонент управляющей логики `labeling/session_manager.py`
Вся файловая логика сессии (стандартная папка, имя, структура, список недавних) выносится в чистый Python-модуль без Qt, чтобы её можно было тестировать как `utils/`/`controller`. Qt используется только в диалоге и главном окне.
- `DEFAULT_SESSION_ROOT = Path.home() / "BacteriaLabeling"` (прежний дефолт из `_open_labeling` сохраняется — точка входа уже консистентна).
- `SESSION_SUBDIRS = ("source", "masks", "cropped", "cropped_masks")`.
- `get_session_root()` / `set_session_root(path)`: текущий корень хранится в конфиге (см. решение 2); по умолчанию `DEFAULT_SESSION_ROOT`. Это закрывает требование «переопределяемое расположение».
- `sanitize_name(name) -> str`: убирает символы, недопустимые в именах папок Windows (`<>:"/\|?*`), обрезает до 60 символов; недопустимое имя (`None`/пусто после очистки) → `Ensure`-ошибка для диалога.
- `ensure_session_structure(session_dir)`: создаёт корень и 4 поддиректории (`mkdir(parents=True, exist_ok=True)`).
- `class SessionManager`: хранит путь к корню (текущее расположение) и список недавних; `current_root`, `set_root(path)`, `list_recent()`, `add(session_dir, name)`, `remove(path)`, `session_path(name)`. Путь к JSON-файлу инъектируется в конструктор для тестируемости (см. решение 2).

### 2. Хранение настроек в JSON в стандартной папке конфигурации
Используется `QStandardPaths.writableLocation(QStandardPaths.StandardLocation.AppConfigLocation)` + `bacteria_analyzer.json`. Формат — один файл с двумя ключами:
```json
{
  "session_root": "/home/user/BacteriaLabeling",
  "recent_sessions": [{ "name": "...", "path": "..." }]
}
```
Порядок: от свежих к старым, максимум 10 записей, без дубликатов (повторное открытие сессии поднимает её в начало). Выбор JSON вместо SQLite/QSettings: лёгкий, легко тестируется, не требует новой зависимости, совместим с Nuitka.
Альтернатива (QSettings ini) отклонена: формат привязан к Qt-сериализации, труднее проверить в тестах.

### 3. Диалог `ui/labeling_session_dialog.py` вместо голого `QFileDialog.getExistingDirectory`
Такой диалог (модальный `QDialog`) содержит:
- поле «Название сессии» (`QLineEdit`, Enter = создать);
- строку «Сессии сохраняются в: <текущий корень>» с кнопкой «✏️ Изменить» — открывает выбор нового корня (`QFileDialog.getExistingDirectory`) и сохраняет его через `SessionManager.set_root`;
- список «Недавние сессии» (`QListWidget`) с кнопкой «Открыть» и двойным кликом;
- кнопку «📂 Открыть существующую папку…» (для продвинутых пользователей);
- кнопки «Создать и открыть» / «Отмена».
При пустом названии кнопка создания неактивна. При совпадении с существующей сессией — предупреждение с выбором «Открыть существующую» (см. спецификацию).

Альтернатива (простой `QFileDialog` как сейчас) отклонена: именно оно и создаёт путаницу.

### 4. `LabelingWindow` всегда работает с поддиректориями
В `__init__`: `ensure_session_structure(self.session_dir)`; `self.source_dir = self.session_dir / "source"`. `_get_current_dir`/`_get_mask_dir` больше не падают в корень: внутренние `get_current_dir`/`get_mask_dir` в `LabelingController` упрощаются до безотказного возврата поддиректории (создают её при отсутствии). Соответствующие тесты обновляются (fallback на корень удаляется).

В окне разметки отображается полный путь: в заголовке окна (`Разметка — <session_dir>`) и отдельная надпись (label) в левой панели с текущей рабочей поддиректорией (`source/` или `cropped/`), обновляемая при переключении режима (`_on_mode_changed`). Это закрывает требование «показывать текущий путь в UI».

### 5. Интеграция в главном окне
`main_window.py::_open_labeling` открывает `LabelingSessionDialog` (модально), по результату:
- создаёт/открывает сессию (`ensure_session_structure`),
- `SessionManager.add(...)`,
- `LabelingWindow(Path, self).show()`.

### 6. Тесты
`tests/test_session_manager.py`: санитизация имён, создание структуры, поведение списка недавних (небывалые пути, дедупликация, лимит 10), работа с инъектированным JSON-путем. `tests/test_labeling_controller.py`: `get_current_dir`/`get_mask_dir` возвращают поддиректории после модификации.

## Risks / Trade-offs

- **Смена поведения для старых сессий**: пользователи с сессиями, где файлы лежат в корне (без `source/`), после открытия легко «увидят» пустую сессию, т.к. работаемая папка становится `source/`. → Смягчение: `ensure_session_structure` вызывается при открытии; файлы в корне не удаляются; опция «Открыть существующую папку» даёт возможность работать с прежней структурой. Это изменение оправдано и зафиксировано в delta-spec.
- **Недопустимые символы Windows в имени**: русский текст допустим, но `\ : /` и т.п. → санитизация и отказ при пустом.
- **Подписка сборки**: новые модули (`labeling/session_manager.py`, `ui/labeling_session_dialog.py`) должны попасть в Nuitka-сборку (в сборку `include` пакеты `ui` и `labeling` целиком — новые файлы внутри них подхватятся при пересборке; проверить скрипт).
- **JSON-файл при первом запуске**: если папки конфигурации нет → создаётся; некорректный JSON обрабатывается как пустой список.

## Migration Plan

1. Выпуск изменения; старые сессии доступны через «Открыть существующую папку…».
2. При первом запуске список недавних пуст — самозаполняется при создании/открытии.
3. Откат: удаление/пересоздание файлов диалога и сессии; конфиг-файл не мешает, если JSON отсутствует.
