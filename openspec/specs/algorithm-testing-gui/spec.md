# algorithm-testing-gui Specification

## Purpose
GUI-окно тестирования алгоритмов распознавания колоний: выбор алгоритмов и датасета, загрузка внешних ONNX-моделей, парное сравнение, экспорт HTML-отчёта и фоновый прогон без блокировки интерфейса.
## Requirements

### Requirement: Testing window entry

Главное окно приложения (`MainWindow`) SHALL предоставлять кнопку/действие открытия окна тестирования алгоритмов. Окно тестирования SHALL открываться как отдельное окно приложения.

#### Scenario: Open from main window
- **КОГДА** пользователь нажимает кнопку «Тестирование алгоритмов» в главном окне
- **ТОГДА** открывается окно тестирования с загруженным списком алгоритмов

### Requirement: Algorithm selection in GUI

Окно тестирования SHALL отображать список доступных алгоритмов (классические + зарегистрированные модели) с чекбоксами, по умолчанию все отмечены. Пользователь SHALL иметь возможность выбрать подмножество для запуска. Сводная таблица результатов SHALL содержать метрики (mean IoU, Dice, F1, Precision, Recall) для каждого выбранного алгоритма.

#### Scenario: Select subset
- **КОГДА** пользователь снимает галочку с алгоритма и запускает прогон
- **ТОГДА** этот алгоритм SHALL NOT запускаться и NOT отображаться в результатах

#### Scenario: Summary table shows algorithms
- **КОГДА** прогон завершён
- **ТОГДА** таблица SHALL показывать по строке на каждый выбранный алгоритм со сводными метриками

### Requirement: Neural model loading in GUI

Окно тестирования SHALL предоставлять кнопку «Загрузить модель (.onnx)» с файловым диалогом выбора внешних весов. После загрузки алгоритм SHALL добавляться в список с учётом параметров инференса.

#### Scenario: Load external model
- **КОГДА** пользователь выбирает валидный файл `.onnx`
- **ТОГДА** модель SHALL добавиться в список алгоритмов и стать доступной для выбора

#### Scenario: Failed load shows error
- **КОГДА** выбран несуществующий файл или невалидная модель
- **ТОГДА** окно SHALL показать сообщение об ошибке, не добавляя алгоритм

### Requirement: Pairwise comparison view

Окно тестирования SHALL предоставлять выбор двух алгоритмов для парного сравнения на одних и тех же изображениях. Результат SHALL отображаться как таблица «победитель по снимку» по выбранным метрикам (IoU, Dice, F1) — на каждом снимку фиксируется алгоритм с большим значением.

#### Scenario: Compare two algorithms
- **КОГДА** выбраны алгоритмы A и B и включён режим сравнения
- **ТОГДА** для каждого снимка для каждой метрики SHALL указываться алгоритм-победитель

### Requirement: Report export from GUI

Окно тестирования SHALL предоставлять кнопку «Экспорт отчёта» для сохранения HTML-отчёта, сгенерированного ядром тестирования (`generate_report`), по пути, выбранному пользователем. Генерация отчёта и запись его содержимого SHALL выполняться вне GUI-потока; окно SHALL показывать состояние экспорта, оставаться отзывчивым и сообщать об успешном завершении или понятной ошибке. Готовый отчёт SHALL публиковаться по выбранному пути только после успешной генерации, чтобы отмена или ошибка не оставляли частичный файл под окончательным именем и SHALL NOT изменяли ранее существовавший отчёт.

#### Scenario: Export HTML report
- **КОГДА** пользователь нажимает «Экспорт отчёта» и выбирает путь
- **ТОГДА** отчёт SHALL быть создан по указанному пути, операция SHALL выполняться вне GUI-потока, а интерфейс SHALL оставаться отзывчивым до сообщения о результате

#### Scenario: Report export fails
- **КОГДА** выбранный путь недоступен или генерация/запись отчёта завершается ошибкой
- **ТОГДА** система SHALL сообщить ошибку, восстановить доступность интерфейса, SHALL NOT сообщать об успешной записи, а существующий файл по целевому пути SHALL остаться неизменённым

### Requirement: Testing runs in blocking off-UI thread

Сканирование и подготовка датасета, чтение/декодирование пар, вычисление алгоритмов и метрик, парное сравнение и агрегация SHALL выполняться вне GUI-потока. Окно SHALL получать обновления состояния и прогресса по мере обработки и оставаться отзывчивым. Заполнение и отображение больших результатов SHALL NOT блокировать GUI-поток; окно SHALL предоставлять действие отмены активного прогона или экспорта. Отмена SHALL останавливать постановку новых задач на безопасной границе; отмена уже выполняющегося native-вызова SHALL оставаться кооперативной. Закрытие окна во время такого вызова SHALL показывать состояние «Завершение…», оставаться отзывчивым и закрываться автоматически после безопасного возврата worker без ожидания в GUI-потоке.

#### Scenario: Progress indicated
- **КОГДА** прогон запущен
- **ТОГДА** окно SHALL показывать прогресс и/или статус, UI не блокируется

#### Scenario: Progress advances during batch evaluation
- **КОГДА** длительный прогон обрабатывает набор пар изображения и маски
- **ТОГДА** UI SHALL показывать текущую фазу и прогресс завершённых задач или пар, принимать события интерфейса и оставаться отзывчивым до завершения

#### Scenario: Large result set is presented
- **КОГДА** завершённый прогон содержит результаты по сотням или тысячам sample/variant
- **ТОГДА** результаты SHALL быть доступны пользователю без синхронного создания GUI-элемента для каждой ячейки в одном блокирующем проходе главного потока

#### Scenario: User cancels or closes a running test
- **КОГДА** пользователь запрашивает отмену прогона либо закрывает окно во время выполнения
- **ТОГДА** окно SHALL показать «Завершение…», оставаться отзывчивым, прекратить планирование новой работы в ближайшей безопасной точке и закрыться автоматически после возврата текущей неотменяемой native-операции без синхронного ожидания в GUI-потоке; уже записанные пользовательские данные SHALL оставаться целыми

#### Scenario: User closes the window during report export
- **КОГДА** пользователь закрывает окно во время генерации/записи отчёта
- **ТОГДА** окно SHALL оставаться отзывчивым в состоянии «Завершение…», остановить публикацию отчёта в выбранный путь и закрыться после безопасного завершения/отмены worker; существующий файл по этому пути SHALL оставаться нетронутым при отмене или ошибке

### Requirement: Progress and errors identify pipeline phase

Окно SHALL различать подготовку датасета, чтение/декодирование, выполнение алгоритмов, вычисление сравнения и формирование результатов. Ошибки SHALL показывать фазу и доступный контекст пары/алгоритма, не представляя ожидающую операцию как зависание или успешный прогон.

#### Scenario: Run waits for image preparation
- **КОГДА** чтение или декодирование входных пар занимает заметное время
- **ТОГДА** UI SHALL показывать состояние подготовки данных и SHALL обновить его при переходе к вычислениям

#### Scenario: Task fails during evaluation
- **КОГДА** отдельная пара не читается либо отдельный алгоритм завершается ошибкой
- **ТОГДА** прогресс SHALL отразить завершение/ошибку этой задачи, а UI SHALL сообщить фазу сбоя, сохранив возможность увидеть успешные результаты остальных задач

### Requirement: Results table stretches to window width

Таблица результатов (и таблица парного сравнения) SHALL растягиваться на всю ширину окна: колонки SHALL автоматически распределяться по доступной ширине (stretch) так, чтобы текст не обрезался и не требовалось вручную растягивать столбцы.

#### Scenario: Table fills window width
- **КОГДА** окно тестирования открыто (и после прогона результатов)
- **ТОГДА** таблица SHALL занимать всю ширину зоны результатов, колонки расширяются автоматически

#### Scenario: Metric columns resize
- **КОГДА** окно изменяется по ширине
- **ТОГДА** колонки таблицы SHALL перераспределяться, содержимое остаётся видимым без ручной настройки ширин

### Requirement: Dataset layout description in GUI

Окно тестирования SHALL отображать рядом с полем «Датасет» пояснение-инструкцию, объясняющую поддерживаемые форматы: legacy-папку с `source/`, `masks/`, `cropped/`, `cropped_masks/`, где изображение и маска пары выбираются по имени, и импортированный датасет с `dataset.json`, в котором записаны относительные пути к изображениям и эталонным маскам. Подсказка SHALL указывать, что импортированный датасет 22022540 можно выбрать непосредственно по корневой папке `datasets/22022540_imported`, и давать доступную ссылку на каталог источников в репозитории проекта `https://github.com/Egel68/bacterial-colony-area/blob/main/docs/datasets.md`. Каталог SHALL содержать первичные ссылки на AGAR, Petri plates, датасет 22022540 и NIST NICE, а также связанные статьи; различать запись датасета, публикацию, программное обеспечение и отдельный файл; сохранять устойчивые версионные ссылки или DOI и подтверждённые сведения о цитировании, доступе и лицензиях. Связь с локальными папками SHALL быть оговорена как непроверенная, если контрольные суммы или полный состав не сверялись; неизвестные сведения не SHALL выводиться только из имён папок.

#### Scenario: Hint shown near dataset field
- **КОГДА** пользователь открывает окно тестирования
- **ТОГДА** под полем выбора датасета отображается текст с описанием legacy- и manifest-структур, включая директории legacy-формата и имя файла `dataset.json`

#### Scenario: Hint mentions four directories
- **КОГДА** пользователь читает подсказку
- **ТОГДА** подсказка упоминает legacy-директории `source/`, `masks/`, `cropped/`, `cropped_masks/`, manifest `dataset.json` и корневую папку `datasets/22022540_imported` для импорта 22022540

#### Scenario: Hint links to dataset-source catalog
- **КОГДА** пользователь видит пояснение у выбора датасета
- **ТОГДА** он может перейти по ссылке на каталог источников проекта, доступный в репозитории по адресу `https://github.com/Egel68/bacterial-colony-area/blob/main/docs/datasets.md`, где зафиксированы первичные источники, версии, цитирование и условия доступа к внешним наборам

#### Scenario: Catalog preserves all supplied source links
- **КОГДА** исследователь открывает каталог датасетов
- **ТОГДА** он находит ссылки AGAR, Figshare Petri plates v2 и связанной статьи MDPI, Figshare 22022540 v3 и связанной статьи Nature, а также запись NIST NICE

#### Scenario: Local copies are not asserted identical without verification
- **КОГДА** документация связывает опубликованный набор с локальной папкой
- **ТОГДА** она описывает наблюдаемый локальный состав и явно указывает на непроверенную идентичность, если хэши или полный состав не сопоставлялись

### Requirement: GUI testing accepts imported manifest dataset

GUI тестирования SHALL запускать выбранные алгоритмы на валидных записях `source` и `cropped`, описанных в `dataset.json`, принимая пути к изображению и маске относительно корня датасета и не требуя совпадения их расширений. Для выхода `CocoBboxImporter` запись cropped-варианта SHALL иметь `id` source-записи с суффиксом `_cropped`; такие записи SHALL оцениваться отдельно как cropped-варианты (`is_cropped=True`) относительно указанных эталонных масок. Лимит образцов SHALL ограничивать число source-изображений и сохранять cropped-варианты соответствующих выбранных source-записей. Запуск SHALL читать датасет, не изменяя исходные изображения, маски или манифест.

#### Scenario: Run GUI test on imported 22022540 root
- **КОГДА** пользователь выбирает `datasets/22022540_imported` и запускает выбранный алгоритм
- **ТОГДА** GUI загружает пары JPEG-изображение и PNG-маска из записей `dataset.json`, запускает алгоритм и показывает метрики вместо сообщения о пустом датасете

#### Scenario: Run cropped variants declared in manifest
- **КОГДА** манифест выбранного датасета содержит source- и cropped-записи для одного снимка
- **ТОГДА** GUI включает обе пары в результат, передаёт cropped-пару с флагом `is_cropped=True` и сохраняет их метрики под соответствующими variant-ами

#### Scenario: Sample limit retains matching cropped records
- **КОГДА** пользователь задаёт лимит source-снимков для manifest-датасета, содержащего cropped-записи
- **ТОГДА** прогон ограничивается выбранным числом source-снимков и включает только cropped-записи тех же выбранных снимков

#### Scenario: Legacy dataset remains supported
- **КОГДА** пользователь выбирает legacy-датасет из `source/` и `masks/` без `dataset.json`
- **ТОГДА** GUI продолжает загружать пары по существующему legacy-контракту и запускать выбранные алгоритмы

#### Scenario: Invalid or empty manifest dataset
- **КОГДА** выбранный manifest пуст или некорректен, не содержит валидных image-mask записей либо указанные в записях файлы отсутствуют
- **ТОГДА** GUI сообщает об отсутствии валидных тестовых образцов или об ошибке загрузки и не запускает пустой прогон

#### Scenario: All manifest files fail to decode during evaluation
- **КОГДА** manifest содержит записи, но планировщик не может прочитать ни одной пары изображения и маски
- **ТОГДА** GUI сообщает, что пары датасета не удалось прочитать, показывает путь хотя бы к одной проблемной паре и доступную причину сбоя, отличая ошибку чтения файлов от ошибки выполнения выбранных алгоритмов

#### Scenario: Manifest files use a Unicode Windows path
- **КОГДА** пользователь запускает manifest-датасет из доступного каталога Windows, абсолютный путь к которому содержит символы Unicode, например `C:/Users/Егор/Desktop/22022540_imported`, а файлы имеют поддерживаемый формат
- **ТОГДА** GUI декодирует изображения и маски и запускает выбранные алгоритмы; допустимые пары не пропускаются только из-за Unicode-символов в пути

#### Scenario: All algorithm tasks fail after manifest pairs are read
- **КОГДА** GUI успешно читает хотя бы одну пару из manifest, но все задачи выбранных алгоритмов завершаются с ошибкой
- **ТОГДА** GUI сообщает, что сбой относится к выполнению алгоритмов, указывает число прочитанных пар и показывает контекст хотя бы одной неуспешной задачи, включая путь к изображению и причину
