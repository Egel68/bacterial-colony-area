# Design

## Context

See proposal.md - Why. В проекте уже есть импортёр COCO-bbox для 22022540, который может фиксировать source-level train/val/test split 70/15/15 с seed 42 и сохранять геометрию чашки при подготовке cropped-данных. Текущий `train-colony` уже изолирует test и формирует отчёт, но жёстко выбирает MobileNetV3-Small U-Net; стандартная архитектура `unet` доступна в основном `train` CLI, который не формирует требуемое парное сравнение на test. Метрики обучения уже считают TP/FP/FN/TN для sample, но нет сводной матрицы ошибок по сопоставимому набору фоновых условий.

Встроенный baseline — `models/colony_seg.onnx` (U-Net). Доступные старые summaries содержат число train/val sample, но не список ID; поэтому принадлежность sample к историческому обучению baseline может оказаться непроверяемой. После ранее прерванного запуска полностью подготовленный каталог можно явно передать через `--reuse-prepared-dataset`; pipeline обязан повторно проверить его split, source coverage, пары и файлы до baseline evaluation.

## Goals / Non-Goals

**Goals:**

- Получать парные белые/чёрные изображения одной формы и с одной GT-маской.
- Сравнивать текущую и переобученную с нуля U-Net на идентичных test ID, отдельно по каждому фону.
- Сохранять воспроизводимые данные разбиения, метрики и provenance в отдельном каталоге эксперимента.
- Выполнять optimizer updates scratch-U-Net только на CUDA GPU; отсутствие CUDA не должно приводить к CPU fallback.

**Non-Goals:**

- Менять пользовательский GUI, инференс-порог или поведение текущей production-модели.
- Автоматически продвигать новую модель в `models/colony_seg.onnx`.
- Менять COCO-аннотации, форму эллиптических GT-масок или заменять ими экспертную пиксельную разметку.

## Decisions

### 1. Расширить `train-colony`, не дублировать training workflow

Добавить явный режим эксперимента с чёрным фоном и выбор архитектуры `unet`; оставить текущий default `mobilenet_v3_small_unet` и его поведение без изменений. Режим `unet` запускается с random initialization, без pretrained-весов и resume, только на CUDA GPU. Это переиспользует имеющиеся импорт, split, test isolation, проверку read-only источника и каталог артефактов; `--reuse-prepared-dataset` разрешает продолжить с уже полностью материализованного каталога `dataset/` после валидации split и всех пар. Альтернатива — отдельный CLI с копированием этих гарантий — отвергнута как дублирование; обычный `train --model unet` недостаточен, так как сам по себе не формирует нужное парное test-сравнение.

### 2. Split исходников до генерации фоновых вариантов

Сохранить существующие 70/15/15, seed 42 и стратификацию по категории COCO. Сначала назначить subset исходным ID и записать split; затем создать варианты. Для преобразования использовать полноразмерные `kind=source` записи и геометрию `dish`, которую импортёр уже определяет для cropped-данных; существующие cropped-записи не включать в эту пару, чтобы не смешивать эффект фона с изменением кадрирования. Вариант меняет только пиксели вне круга чашки, а GT-маска остаётся общей/попиксельно идентичной. Неизвестная геометрия — ошибка с ID sample, а не тихий пропуск.

Все производные записи наследуют subset исходника. Полный набор source/black пар и split материализуются и валидируются до baseline evaluation и обучения; неполный набор останавливает run. Baseline evaluation на original/black test допускается до обучения и не влияет на веса/гиперпараметры; test не участвует в optimizer или выборе checkpoint. Train включает обе версии train-ID, val используется для выбора checkpoint, а post-training оценка новой модели выполняется только после фиксации лучшего checkpoint. Исходный каталог и уже импортированный датасет остаются read-only.

### 3. Учитывать baseline и новую модель в одном парном протоколе

Перед оптимизацией измерить текущий bundled U-Net, после обучения — новый `unet` checkpoint/ONNX. Оба запуска используют одни test ID, исходные GT-маски, одинаковый resize/tiled inference path и фиксированный бинарный порог 0.5 для white и black версий. Test не используется для настройки гиперпараметров. Если нельзя восстановить исторический список train ID baseline, в отчёте ставится `baseline_training_overlap=unknown`; метрики остаются парными по ID, но не называются подтверждённой независимой оценкой baseline.

### 4. Обучать scratch-U-Net только на CUDA

Для режима black-background задавать `device=cuda` и проверять фактическую доступность CUDA до optimizer updates. Отсутствие GPU должно приводить к ясной ошибке, без тихого CPU fallback; summary фиксирует имя устройства. Baseline ONNX inference может оставаться CPU-only и должен завершиться на обоих вариантах test до начала обучения.

### 5. Сводить матрицу на уровне пикселей

Суммировать TP/FP/FN/TN по всем пикселям test-набора отдельно для каждой модели и фонового условия; precision/recall вычислять из сумм, не усреднять их между кадрами. Матрица фиксируется как строки actual `[background, colony]`, столбцы predicted `[background, colony]`: `[[TN, FP], [FN, TP]]`. Дополнительно сохранять per-sample счётчики и метрики, чтобы локализовать ложноположительные кадры.

Канонический результат — `report.json` с полным split и per-sample данными; короткий `comparison.html` показывает четыре сводных условия (baseline/new × white/black) и матрицы ошибок. В отчёте также фиксируются seed, ratio, threshold, архитектура/инициализация и статус происхождения baseline.

## Risks / Trade-offs

- [Ошибка авто-геометрии чашки] → неверная область будет закрашена; валидировать границы круга, проверять трансформацию на тестовых образцах и останавливать подготовку при отсутствующей геометрии.
- [Исторические train ID baseline не сохранены] → независимость исходных метрик нельзя гарантировать; явно маркировать статус как unknown, сохранять paired ID и не делать claims о holdout baseline.
- [COCO bbox превращены в эллиптические маски] → precision/recall отражают согласие с этой растеризованной разметкой, а не независимую экспертную пиксельную истину; указывать происхождение GT в отчёте.
- [CUDA недоступна на машине запуска] → baseline может быть посчитан на CPU, но обучение не начинается и CPU fallback запрещён; запускать experiment следует в `.venv-full` с доступной GPU.
- [Пиксельные метрики зависят от большого числа фоновых пикселей] → публиковать вместе с матрицей и per-sample результатами, а не только accuracy; отдельно сравнивать false-positive counts между фонами.

## Migration Plan

Миграции production-данных не требуются. Эксперимент создаёт новый output-каталог и не меняет source dataset, существующие веса или пользовательский inference. Rollback — удалить отдельный каталог запуска; использование нового ONNX в приложении возможно только отдельным явным решением после анализа отчёта и вне этой задачи.
