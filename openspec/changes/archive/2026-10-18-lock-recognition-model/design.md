# Design

## Context

См. [proposal.md](proposal.md) — мотивация и объём. Сейчас `ui/analysis_window.py` динамически заполняет список из реестра, содержит ветку классического анализа и набор её параметров, а также позволяет вручную изменять геометрию чашки. Главное окно предоставляет вход в `ui/testing_window.py`, где можно выбирать алгоритмы и загружать внешние модели. Встроенная модель `NN:colony_seg` регистрируется при старте, и анализ/ONNX-инференс уже поддерживают фоновые операции и диагностику.

## Goals / Non-Goals

**Goals:**
- Создать один стабильный пользовательский путь: автоматически обнаружить начальную область, дать возможность скорректировать её и выполнить инференс только `NN:colony_seg`.
- Не скрыть только виджеты визуально, а устранить выбор алгоритма и его tuning-контролы; предусмотреть отсутствие модели/ошибку авто-поиска без переключения алгоритма.
- Сохранить независимые возможности просмотра и экспорта результатов.
- Убрать доступ к алгоритмическому GUI тестированию из обычного пользовательского приложения, не ломая инструменты разработчика.

**Non-Goals:**
- Запретить альтернативные алгоритмы в Python API, CLI или тестовом реестре.
- Переопределять порядок версий модели, менять ONNX-веса, пересматривать порог сегментации или проводить клиническую валидацию.

## Decisions

1. **Основной анализ вызывает фиксированный алгоритм по стабильному идентификатору, а не выбирает первый доступный в реестре.** Это предотвращает зависимость поведения от порядка регистрации и случайное использование другой bundled-модели. При отсутствии `NN:colony_seg` отображается ошибка; fallback запрещён. Альтернатива — оставить динамический combo с единственным пунктом — отклонена: это сохраняет лишнее понятие выбора и хрупкость списка.

2. **Убрать параметры алгоритма и классическую ветку, но сохранить редактирование круглой области анализа.** Автопоиск задаёт исходный центр и радиус; пользователь может переместить круг и изменить радиус для коррекции неточного обнаружения. Предсказание и метрики ограничиваются актуальной круглой областью; явное действие «Пересчитать» запускает фиксированную модель по обновлённой геометрии. Изменение геометрии не добавляет настроек модели. Если автопоиск не обнаружил чашку, показать ошибку и не подставлять искусственную геометрию. Альтернатива — полностью запретить ручную коррекцию — отклонена, поскольку автоопределение может выделять область неточно.

3. **Спрятать GUI тестирования со стороны главного пользовательского окна, сохранив его модуль и CLI для внутренней работы.** Это обеспечивает отсутствие пользовательского пути к сравнению и загрузке весов без удаления полезной валидационной инфраструктуры. Не считать это границей безопасности: ручной запуск Python-модуля не блокируется. Альтернатива — удалить тестовый функционал целиком — отклонена как избыточное ограничение разработчиков.

4. **Сохранить обработку фиксированной модели через существующий асинхронный pipeline.** Изменённые пользователем геометрия круга и generation/token операции должны попадать в snapshot запуска, чтобы результат устаревшего расчёта не заменил результат для новой области. Не менять tiled CPU-инференс, отмену, прогресс, отображение и экспорт вне применения ROI и её метрик. Это минимизирует регрессионный риск производительности.

## Risks / Trade-offs

- [Автопоиск может определить круг неточно] → показывать обнаруженную область и позволять пользователю скорректировать центр/радиус перед повторным анализом; при полном отсутствии обнаружения сообщать об ошибке и не создавать искусственную геометрию.
- [Отсутствующая/повреждённая модель делает основной анализ недоступным] → fail-closed поведение с конкретным сообщением; включить проверку bundled-модели в сборочный smoke test.
- [Пользователь может считать закрытость настроек доказательством клинической валидации] → явно разделить интерфейсную стандартизацию и подтверждение клинической пригодности в релизной документации.
- [Внутренний GUI testing может оставаться импортируемым/запускаемым напрямую] → считать это инженерным инструментом; пользовательский пакет не предоставляет к нему видимый entry point.

## Migration Plan

1. Изменить пользовательский путь и GUI-доступ к тестированию, сохранив алгоритмы и CLI для разработки.
2. Обновить GUI-тесты и документацию по пользовательским настройкам.
3. Проверить обычную сборку: bundled `NN:colony_seg` запускается, альтернативы недоступны из пользовательских окон, ошибка модели/авто-поиска понятна, корректировка центра/радиуса ограничивает инференс и показатели текущей областью, существующие сценарии просмотра и сохранения работают.
4. Откат — вернуть вызов алгоритмического окна и UI выбора из предыдущей версии; изменения пользовательских файлов/датасетов не затрагиваются.

## Open Questions
