# labeling-session-setup Specification

## Purpose
Удобное создание и открытие сессий разметки без необходимости вручную указывать папку и понимать внутреннюю структуру директорий.

## ADDED Requirements

### Requirement: Custom session name

Пользователь SHALL иметь возможность задать каждой сессии произвольное пользовательское название через поле «Название сессии» в диалоге. Такое название SHALL становится именем папки сессии: русские буквы, пробелы и другие допустимые в именах папок символы разрешены; символы, недопустимые в именах папок Windows (`<>:"/\|?*`), SHALL быть удалены из имени автоматически. После очистки имя SHALL быть непустым, иначе сессия не создаётся. Если сессия с таким названием уже существует в выбранном корне, система SHALL предложить открыть её или ввести другое название.

#### Scenario: Arbitrary custom name

- **КОГДА** пользователь ввёл название «Чашка #1 — эксперимент»
- **ТОГДА** создаётся папка `<корень>/Чашка #1 — эксперимент/` и открывается окно разметки

#### Scenario: Name with invalid Windows characters

- **КОГДА** пользователь ввёл «фото:эксперимент/31» 
- **ТОГДА** имя SHALL быть очищено до «фотоэксперимент31» (символы `: /` удалены)

#### Scenario: Empty or invalid-only session name

- **КОГДА** поле «Название сессии» пусто или после удаления недопустимых символов не осталось символов
- **ТОГДА** кнопка «Создать и открыть» SHALL быть неактивной или показываться сообщение об ошибке, сессия не создаётся

#### Scenario: Existing session name

- **КОГДА** введённое название уже существует в выбранном корне
- **ТОГДА** система SHALL сообщить об этом и предложить открыть существующую сессию или изменить название

### Requirement: Auto-create session structure

Система SHALL гарантировать наличие поддиректорий `source/`, `masks/`, `cropped/`, `cropped_masks/` внутри любой открываемой или создаваемой сессии, создавая отсутствующие при открытии.

#### Scenario: Open existing session without subdirs

- **WHEN** пользователь открывает существующую папку, в которой нет поддиректорий
- **ТОГДА** система SHALL создать недостающие поддиректории и открыть окно разметки

#### Scenario: Subdirs already exist

- **WHEN** пользователь открывает сессию со всеми поддиректориями
- **ТОГДА** поддиректории SHALL не пересоздаваться и существующие файлы остаются неизменными

### Requirement: Configurable session storage location

Система SHALL хранить сессии в стандартной папке `<дом пользователя>/BacteriaLabeling` по умолчанию. Пользователь SHALL иметь возможность переопределить эту папку через диалог («сменить расположение сессий»). Выбранное расположение SHALL сохраняться между запусками. Новые сессии SHALL создаваться внутри текущего выбранного расположения.

#### Scenario: Default storage location

- **КОГДА** пользователь ещё не менял расположение сессий
- **ТОГДА** новые сессии создаются в `<дом пользователя>/BacteriaLabeling/`

#### Scenario: Override storage location

- **КОГДА** пользователь в диалоге выбрал другое расположение, например `D:/Мои проекты/Разметка`
- **ТОГДА** новые сессии создаются в `D:/Мои проекты/Разметка/`, а выбор сохраняется для последующих запусков

#### Scenario: Override persists across launches

- **КОГДА** пользователь переопределил расположение и перезапустил приложение
- **ТОГДА** диалог использует сохранённое расположение как текущее

### Requirement: Show current session path in UI

Окно разметки SHALL отображать полный путь к текущей рабочей директории сессии (корень сессии и активную поддиректорию `source/` или `cropped/`), чтобы пользователь всегда понимал, с какой папкой ведётся работа.

#### Scenario: Session path visible on open

- **КОГДА** пользователь открывает сессию «Эксперимент»
- **ТОГДА** в окне разметки SHALL отображаться путь вида `<корень>/Эксперимент/` и рабочая поддиректория

#### Scenario: Path updates with mode switch

- **КОГДА** пользователь переключается между «Исходные изображения» и «Обрезки чашек»
- **ТОГДА** отображаемый путь SHALL соответствовать текущей рабочей поддиректории (`source/` или `cropped/`)

### Requirement: Recent sessions list

Система SHALL хранить список недавних сессий и отображать его в диалоге настройки сессии. Каждая запись SHALL содержать путь к сессии и название. При открытии сессии из списка она SHALL добавляться в начало списка. Дубликаты SHALL удаляться. Список SHALL храниться в JSON-файле в стандартной папке конфигурации пользователя и переживать перезапуск приложения.

#### Scenario: Show recent sessions

- **WHEN** пользователь открыл ранее 3 сессии и снова открывает диалог настройки
- **ТОГДА** диалог SHALL показать эти 3 сессии, самая новая — первой

#### Scenario: Open recent session

- **WHEN** пользователь выбирает одну из недавних сессий
- **ТОГДА** opening session поддиректории проверяются/создаются и открывается окно разметки

#### Scenario: No recent sessions

- **WHEN** список ещё пуст (первый запуск)
- **ТОГДА** диалог SHALL показать только кнопку создания новой сессии и открытия произвольной папки

### Requirement: Open arbitrary folder

Система SHALL предоставлять опцию «Открыть существующую папку», которая позволяет выбрать произвольную директорию через стандартный диалог файлов и открыть её как сессию разметки (с автосозданием поддиректорий).

#### Scenario: Open arbitrary folder as session

- **WHEN** пользователь выбрал произвольную папку через диалог
- **ТОГДА** система SHALL открыть окно разметки для выбранной папки и добавить её в список недавних сессий
