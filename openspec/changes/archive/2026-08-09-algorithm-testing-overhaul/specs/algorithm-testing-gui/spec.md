## ADDED Requirements

### Requirement: Testing window entry

Главное окно приложения (`MainWindow`) SHALL предоставлять кнопку/действие открытия окна тестирования алгоритмов. Окно тестирования SHALL открываться как отдельное окно приложения.

#### Scenario: Open from main window
- **КОГДА** пользователь нажимает кнопку «Тестирование алгоритмов» в главном окне
- **ТОГДА** открывается окно тестирования с загруженным списком алгоритмов

### Requirement: Algorithm selection in GUI

Окно тестирования SHALL отображать список доступных алгоритмов (классические + зарегистрированные модели) с чекбоксами, по умолчанию все отмечены. Пользователь SHALL иметь возможность выбрать подмножество для запуска. Сводная таблица результатов SHALL содержать метрики (mean IoU, Dice, F1, Precision, Recall) для каждого выбранного алгоритма.

#### Scenario: Select subset
- **КОГДА** пользователь снимает галочку с алгоритма и запускает прогон
- **ТОГДА** этот алгоритм SHALL NOT запускаться и NOT отображаться в результатах

#### Scenario: Summary table shows algorithms
- **КОГДА** прогон завершён
- **ТОГДА** таблица SHALL показывать по строке на каждый выбранный алгоритм со сводными метриками

### Requirement: Neural model loading in GUI

Окно тестирования SHALL предоставлять кнопку «Загрузить модель (.onnx)» с файловым диалогом выбора внешних весов. После загрузки алгоритм SHALL добавляться в список с учётом параметров инференса.

#### Scenario: Load external model
- **КОГДА** пользователь выбирает валидный файл `.onnx`
- **ТОГДА** модель SHALL добавиться в список алгоритмов и стать доступной для выбора

#### Scenario: Failed load shows error
- **КОГДА** выбран несуществующий файл или невалидная модель
- **ТОГДА** окно SHALL показать сообщение об ошибке, не добавляя алгоритм

### Requirement: Pairwise comparison view

Окно тестирования SHALL предоставлять выбор двух алгоритмов для парного сравнения на одних и тех же изображениях. Результат SHALL отображаться как таблица «победитель по снимку» по выбранным метрикам (IoU, Dice, F1) — на каждом снимку фиксируется алгоритм с большим значением.

#### Scenario: Compare two algorithms
- **КОГДА** выбраны алгоритмы A и B и включён режим сравнения
- **ТОГДА** для каждого снимка для каждой метрики SHALL указываться алгоритм-победитель

### Requirement: Report export from GUI

Окно тестирования SHALL предоставлять кнопку «Экспорт отчёта» для сохранения HTML-отчёта, сгенерированного ядром тестирования (`generate_report`), по пути, выбранному пользователем.

#### Scenario: Export HTML report
- **КОГДА** пользователь нажимает «Экспорт отчёта» и выбирает путь
- **ТОГДА** файл HTML SHALL быть создан по указанному пути

### Requirement: Testing runs in blocking off-UI thread

Прогон алгоритмов SHALL выполняться в фоне (без блокировки UI), с индикацией прогресса в окне тестирования. Интерфейс SHALL оставаться отзывчивым во время прогона.

#### Scenario: Progress indicated
- **КОГДА** прогон запущен
- **ТОГДА** окно SHALL показывать прогресс и/или статус, UI не блокируется

### Requirement: Results table stretches to window width

Таблица результатов (и таблица парного сравнения) SHALL растягиваться на всю ширину окна: колонки SHALL автоматически распределяться по доступной ширине (stretch) так, чтобы текст не обрезался и не требовалось вручную растягивать столбцы.

#### Scenario: Table fills window width
- **КОГДА** окно тестирования открыто (и после прогона результатов)
- **ТОГДА** таблица SHALL занимать всю ширину зоны результатов, колонки расширяются автоматически

#### Scenario: Metric columns resize
- **КОГДА** окно изменяется по ширине
- **ТОГДА** колонки таблицы SHALL перераспределяться, содержимое остаётся видимым без ручной настройки ширин

### Requirement: Dataset layout description in GUI

Окно тестирования SHALL отображать рядом с полем «Датасет» пояснение-инструкцию, объясняющее пользователю, что считается датасетом: папка с четырьмя поддиректориями `source/`, `masks/`, `cropped/`, `cropped_masks/`, где исходные изображения сочетаются с эталонными масками по имени файла.

#### Scenario: Hint shown near dataset field
- **КОГДА** пользователь открывает окно тестирования
- **ТОГДА** под полем выбора датасета отображается текст с описанием структуры датасета

#### Scenario: Hint mentions four directories
- **КОГДА** пользователь читает подсказку
- **ТОГДА** подсказка SHALL упоминать директории `source/`, `masks/`, `cropped/`, `cropped_masks/` и правило пары «изображение + маска»
