# Project Instructions & Harness Rules

## 1. Spec-Driven Development is MANDATORY
Для любой задачи, занимающей более 15 минут, ты ОБЯЗАН использовать OpenSpec. 
Никогда не начинай писать код, пока не создана и не одобрена спецификация через `/opsx:propose`.

## 2. Artifact Authority
Единственным источником истины для требований является директория `openspec/`. 
Если возникает конфликт между твоими внутренними рассуждениями и файлом `openspec/changes/.../specs/*.md`, файл спецификации всегда побеждает.

## 3. Execution Discipline (Addy's Skills)
При выполнении команд `/opsx:apply` или ручной реализации задач из `tasks.md`:
- Активируй скилл `test-driven-development`.
- Активируй скилл `incremental-implementation`.
- "Кажется правильным" не является приемлемым результатом. Ты должен предоставить вывод успешного выполнения тестов или линтера как доказательство.

## 4. The Harness Loop
Если тесты падают или линтер выдает ошибки:
1. Остановись.
2. Прочитай ошибку.
3. Сверься со спецификацией в `openspec/`.
4. Исправь код.
5. Повтори проверку. Не переходи к следующей задаче, пока текущая не будет полностью зеленой.
